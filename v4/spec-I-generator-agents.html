Specification I — V3 · New
Generator Agents
Two new agents that bridge the gap between architecture and code: the Code Task Generator decomposes approved architecture into atomic implementation tasks, and the Test Case Generator writes test cases before the Code Agent writes a single line — enforcing test-driven development across the entire pipeline.
2 Generator Agents Version: 3.0 Status: Draft May 2026

Overview #overview

In V2, the Architecture Agent both designed the system and created implementation tasks. In V3 these responsibilities are separated. The Architecture Agent focuses exclusively on system design. A dedicated Code Task Generator reads the approved architecture and produces the implementation task list. A Test Case Generator then reads both the architecture and the task list to write test cases before any code is produced.

AgentInputOutputReviewed By
Code Task GeneratorApproved architectureImplementation task listTask Review Agent
Test Case GeneratorApproved tasks + architectureTest case specifications per taskTest Case Review Agent

TDD Enforcement #tdd

Core Principle
Test cases are written and approved before the Code Agent writes a single line of source code. The Code Agent receives approved test cases as a contract and writes code that satisfies them. This is test-driven development enforced at the pipeline level — not as a cultural guideline but as a hard architectural constraint.

This means the Code Agent is never guessing what "correct" means. It has a precise, reviewed, approved specification of what correctness looks like for every task. First-pass code quality improves significantly. The number of bug tickets created by the Build & Test Monitor drops because many issues that would have been discovered after the fact are now prevented before the code is written.

Test cases are also written with full knowledge of the architecture — so they test the exact interface signatures, data shapes, and error codes defined by the Architecture Agent. There is no mismatch between what the test expects and what the architecture specifies.

01 — Code Task Generator Agent #task-generator

G1
Code Task Generator Agent
Decomposes approved architecture into atomic implementation tasks
Claude Sonnet API CPU droplet 2,048 token budget
Triggers on
Architecture Review Agent approves the architecture — all five architecture artifacts are marked APPROVED in Jira.
Reads
System architecture document · Data model · Interface contracts · ADRs · Approved functional spec
Produces
A list of 4–15 atomic implementation tasks. Each task is scoped to what one Code Agent session can implement against defined interface contracts. No task spans multiple interface boundaries.
Does NOT do
Make architecture decisions. If the architecture is ambiguous, the Code Task Generator flags the gap and routes back to the Architecture Agent — it does not guess.
Model
Claude Sonnet API — reasoning-heavy task, not code generation. Sonnet is optimal for understanding architecture documents and producing structured decompositions.
Hardware
CPU droplet only. No GPU needed — this is document analysis and structured output generation, not LLM inference at scale.

Flow #task-gen-flow

Architecture Agent → APPROVED (all 5 artifacts) ↓ Code Task Generator reads: architecture + spec ↓ Produces: implementation task list (JSON) ↓ Task Review Agent evaluates (up to 3 cycles) ↓ APPROVED → tasks created in Jira as TASK_DRAFT status ↓ Test Case Generator begins (reads approved tasks) ↓ TASKS REMAIN IN TASK_DRAFT until test cases approved ↓ Test Case Review Agent approves test cases ↓ Tasks promoted to QUEUED → Code Agent can dequeue

Note that tasks are created in TASK_DRAFT status — not QUEUED. The Code Agent cannot pick up a task until its test cases have been written and approved. Only after the Test Case Review Agent marks the test cases as APPROVED are the corresponding tasks promoted to QUEUED status and made available to the Code Agent.

02 — Test Case Generator Agent #testcase-generator

G2
Test Case Generator Agent
Writes test cases before Code Agent writes source code
Qwen2.5-Coder-32B · L40S 2,048 token budget Runs before Code Agent
Triggers on
Task Review Agent approves the task list. Tasks exist in TASK_DRAFT status. Code Agent has not started.
Reads
Approved task list · Interface contracts · Data model · Functional spec acceptance criteria · Architecture ADRs
Produces
For each implementation task: a set of test case specifications covering happy path, error paths, boundary conditions, and edge cases. Test cases are written as executable specifications — not prose descriptions.
Language aware
Generates test cases in the language and test framework specified by the architecture. Rust → #[test] with assert! macros. Python → pytest fixtures. TypeScript → Jest describe/it blocks. The generated test code must be syntactically valid and runnable.
Model
Qwen2.5-Coder-32B on L40S — a code generation model, not a reasoning model. Test cases are code. The same model that will write source code writes the tests so there is zero style mismatch.
Critical constraint
The Code Agent is blocked from starting any task until that task has approved test cases. This is enforced by task status — tasks remain TASK_DRAFT until test cases are APPROVED.

Flow #testcase-flow

Task Review Agent → tasks APPROVED (in TASK_DRAFT) ↓ Test Case Generator reads: tasks + architecture + spec Generates test cases for ALL tasks in parallel (one per task) ↓ Test Case Review Agent evaluates (up to 3 cycles per task) ↓ APPROVED → test cases committed to test/ directory corresponding task promoted TASK_DRAFT → QUEUED ↓ Code Agent dequeues task Reads: task spec + approved test cases + architecture Writes source code that satisfies the test cases ↓ Code Review Agent evaluates source code (up to 3 cycles) ↓ APPROVED → committed to customer branch Customer CI/CD picks up the commit

V3 Key Difference
Every bug fix produced by the Code Agent in steps 7–9 also goes through the Code Review Agent (step 5 loop) before being committed. Review is not just for new feature code — it applies to every line the Code Agent writes, including hotfixes from monitoring agents.
