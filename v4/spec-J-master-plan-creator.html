Specification J — V4 · Foundation
Master Plan Creator Agent
The brain of V4. Takes any human goal — from booking a vacation to starting a company — understands the user's full situation through conversation, and assembles a bespoke agent graph to achieve it. Automates to the maximum possible level for every task.
V4 CoreVersion: 4.0Status: DraftMay 2026

V4 Vision #vision

Core Principle
The user describes any goal in plain language. FORGE understands their current situation, constraints, and preferences. It builds a plan with options. The user chooses one. FORGE assembles the exact agents needed and executes — automating every task to the maximum possible level. Some tasks complete autonomously. Some prepare everything for a single human click. Some produce a document for human action. The platform always pushes as far as it can go.

V4 is not a software factory. It is a universal autonomous agent platform. The same platform that writes and deploys code can plan a vacation, build a business plan, create a study curriculum, or research a legal structure. The domain changes. The agent graph changes. The execution methods change. The underlying architecture — Intake → Plan → Options → Execute → Deliver — stays the same.

V3 had a fixed agent pipeline for software. V4 has a dynamic agent graph for any goal. When V4 detects a software goal, it instantiates the V3 pipeline as its execution graph. V3 becomes a domain specialization of V4.

Intake Agent #intake

I
Intake Agent
Understands the user before the plan begins
Claude Sonnet API Conversational Builds user profile Domain detector
Purpose
Conduct a structured intake conversation to build a complete user profile before any planning begins. The same goal — "plan a vacation to Tahiti" — has completely different optimal paths depending on who is asking. The Intake Agent discovers who is asking.
Approach
One question at a time. Never more than one question per message. Questions are adaptive — the next question depends on the previous answer. The agent stops when it has enough to produce meaningful options, not when it has answered a fixed questionnaire.
Model
Claude Sonnet API — conversational, empathetic, reads between the lines. Detects signals the user did not explicitly state (e.g. "I want to go business class but I know it's expensive" signals aspiration + budget consciousness).
Stops when
It has: (1) understood the goal with enough specificity to plan, (2) identified current state and available resources, (3) understood at least the top 2 constraints, (4) detected the user's risk and effort tolerance.

Master Plan Creator Agent #master-plan

M
Master Plan Creator Agent
Builds the bespoke agent graph for this user + this goal
Claude Opus API Generates agent specs 2-3 distinct options Assigns exec levels
Purpose
Given the user profile and goal, produce 2-3 distinct strategic options — each with a different tradeoff — and for each option, generate the complete agent graph needed to execute it including: which agents run, what each produces, what its review agent checks, what execution level each task gets, and what the final deliverables are.
Model
Claude Opus API — the most capable model for complex multi-domain reasoning. Generating an accurate, realistic plan for "start a dental practice" requires genuine domain knowledge, not just template completion.
Options must be genuinely different
Not just "expensive vs cheap." Each option represents a distinct strategic approach with different tradeoffs. For Tahiti: Option A = maximize points value (complex, high reward), Option B = pure cash (simple, flexible), Option C = hybrid with new card sign-up bonus (moderate effort, high value).
Generates agent prompts
For every producer agent in the chosen option's graph, the Master Plan Creator writes the system prompt that agent will use. These prompts are domain-specific and user-specific — the Tahiti research agent gets a different prompt than the dental practice market analysis agent, and both are personalized to this user's profile.
Generates review rubrics
For every review agent in the graph, the Master Plan Creator generates the review rubric. A Travel Itinerary Review Agent gets different criteria than a Business Plan Review Agent. Both are generated fresh for each plan.

Option Generation #options

The Master Plan Creator always generates 2-3 options. Each option has a name, a one-line strategic thesis, an estimated outcome, a cost/effort/time estimate, and the complete agent graph for execution. The options are presented to the user as a visual artifact — a rich card interface — before any execution begins.

Execution Levels #exec-levels

Every task in every plan has an execution level. The Master Plan Creator assigns the level based on what is technically automatable and what requires human authority. The goal is always to push as far as possible toward Level 3.

LevelNameWhat the platform doesWhat the human doesExamples
Level 3 Fully Autonomous Executes the task completely using APIs, web automation, or direct integration. Delivers the result. Nothing — sees the completed result Book a flight using stored card, search for award availability, commit code to branch, create a document
Level 2 One-Click Execute Prepares everything — fills forms, stages the transaction, pre-populates all fields. Delivers a ready-to-submit artifact. Single click or confirmation to submit Credit card application pre-filled, points transfer form ready, legal document ready to sign, email drafted and ready to send
Level 1 Advise and Deliver Researches, analyzes, and produces a complete document or recommendation. Cannot automate the action itself. Reads the deliverable and acts manually Regulatory requirements document, salary negotiation strategy, dietary restriction research, study schedule

A single plan will typically contain all three levels. The Tahiti Option A example above has Level 3 tasks (book the flight), Level 2 tasks (transfer points — requires user confirmation), and Level 1 tasks (allergy research — cannot be automated). The Master Plan Creator assigns the highest achievable level to each task.

Plan Review Agent #plan-review

PR
Plan Review Agent
Reviews the master plan before it is shown to the user
Claude Sonnet API Max 3 cycles User-profile-aware
Reviews
The full master plan — all options, all task graphs, all execution levels — before it is presented to the user.
Checks
Options are genuinely distinct (not variations of the same approach) · Constraints in the user profile are all respected · Execution levels are accurate (not over-promising Level 3 for tasks that require human authority) · Estimates are realistic · No critical tasks are missing from the graph
Has access to
Full user profile · The goal · All three options and their task graphs · Domain knowledge base for the detected domain
Output
APPROVED — plan shown to user. OR: revision tasks for the Master Plan Creator with specific issues found. Max 3 cycles then human review.

Domain Registry #domains

The Domain Registry is a knowledge store that the Master Plan Creator consults when building plans. Each domain entry contains: typical goals, available execution agents, common constraints, typical deliverables, and which tasks are automatable to Level 3 vs require human authority.
